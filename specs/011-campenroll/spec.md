# Feature: สมัครเข้าร่วมค่าย (Camp Enroll)
Spec ID: SPEC-ENR-011 | Source: SRS v1.0 (UC-11) | Use case: UC-11
Owner: ทีมพัฒนาระบบค่าย | Status: Draft v2 | Updated: 2569-10-21

## Goal
นักศึกษาสามารถสมัครเข้าร่วมค่ายที่เปิดรับสมัคร โดยกรอกข้อมูลที่จำเป็นและแนบเอกสารตามที่ระบบกำหนด
นักศึกษาสามารถบันทึกและกลับมากรอก Draft ของตนเองต่อได้ โดย Draft ยังไม่ถือเป็นใบสมัครที่ส่งแล้ว
เมื่อส่งข้อมูลที่ผ่านการตรวจสอบ ระบบจะเปลี่ยนเป็นใบสมัครสถานะ `submitted` ซึ่งแสดงแก่ผู้สมัครว่า "รอตรวจสอบ"

## Scope
### In scope
- แสดงค่ายที่เปิดรับสมัครให้นักศึกษาเลือก
- กรอกข้อมูลสมัครเข้าร่วมค่าย
- แนบเอกสารที่จำเป็นตามที่ระบบกำหนด
- บันทึกและโหลด Draft แยกตามบัญชีผู้สมัครและค่าย รวมถึงเอกสารที่แนบไว้
- ตรวจสอบความครบถ้วนและรูปแบบของข้อมูลสมัคร
- ตรวจสอบความครบถ้วนและรูปแบบของเอกสาร
- บันทึกข้อมูลการสมัคร
- กำหนดสถานะผู้สมัครเป็น "รอตรวจสอบ"
- แสดงเฉพาะใบสมัครที่ส่งแล้วในรายการสำหรับเจ้าหน้าที่ตรวจสอบ

### Out of scope
- การตรวจสอบและอนุมัติใบสมัครโดยคณะกรรมการ
- การคัดเลือกผู้เข้าร่วมค่าย
- การจัดกลุ่มหรือฝ่ายงานของผู้เข้าร่วม
- การแก้ไขข้อมูลหลังส่งใบสมัคร
- การประกาศรายชื่อผู้ผ่านการคัดเลือก

## Constraints
- CON-ENR-01 ระบบต้องเปิดรับสมัครก่อนที่นักศึกษาจะสามารถสมัครเข้าร่วมค่ายได้
- CON-ENR-02 นักศึกษาต้องเข้าสู่ระบบก่อนดำเนินการสมัคร และเข้าถึงหรือแก้ไข Draft ได้เฉพาะของบัญชีตนเอง
- CON-ENR-03 นักศึกษาต้องกรอกข้อมูลที่ระบบกำหนดให้ครบถ้วนก่อนยืนยันการส่งใบสมัคร แต่บันทึก Draft ที่ยังไม่ครบได้
- CON-ENR-04 เอกสารที่แนบต้องเป็นไปตามรูปแบบที่ระบบกำหนดก่อนยืนยันการส่งใบสมัคร
- IF-ENR-01 ระบบต้องตรวจสอบข้อมูลสมัครก่อนบันทึกเป็นใบสมัครที่ส่งแล้ว การบันทึก Draft ไม่ต้องผ่านการตรวจสอบความครบถ้วน
- IF-ENR-02 ระบบต้องตรวจสอบเอกสารที่แนบก่อนบันทึกเป็นใบสมัครที่ส่งแล้ว การบันทึก Draft สามารถเก็บเอกสารที่ยังไม่ครบหรือยังไม่ผ่านการตรวจสอบได้

## Requirements
- FR-ENR-01 ระบบต้องแสดงค่ายที่เปิดรับสมัครให้นักศึกษาเลือก   <- UC-11 main flow ขั้น 2
- FR-ENR-02 ระบบต้องให้นักศึกษากรอกข้อมูลที่จำเป็นสำหรับการสมัครเข้าร่วมค่าย และบันทึก/โหลด Draft ของตนเองแยกตามค่ายได้   <- UC-11 main flow ขั้น 3
- FR-ENR-03 หากข้อมูลสมัครไม่ครบถ้วนเมื่อยืนยันการส่ง ระบบต้องแจ้งเตือนและระบุช่องข้อมูลที่ต้องแก้ไข โดยคงข้อมูลไว้เป็น Draft   <- UC-11 alternative flow 3a
- FR-ENR-04 ระบบต้องให้นักศึกษาแนบเอกสารที่จำเป็นตามที่กำหนดและเก็บเอกสารนั้นไว้ใน Draft ได้  <- UC-11 main flow ขั้น 4
- FR-ENR-05 หากเอกสารไม่ครบถ้วนหรือไม่ตรงตามรูปแบบ ระบบต้องแจ้งเตือนให้นักศึกษาแนบเอกสารใหม่   <- UC-11 alternative flow 4a
- FR-ENR-06 เมื่อข้อมูลและเอกสารครบถ้วน ระบบต้องให้นักศึกษายืนยันการส่งข้อมูลสมัคร   <- UC-11 main flow ขั้น 5
- FR-ENR-07 เมื่อยืนยันการสมัครสำเร็จ ระบบต้องตรวจสอบและบันทึกข้อมูลเป็นใบสมัครสถานะ `submitted` ให้เจ้าหน้าที่เห็นในรายการตรวจสอบ และแสดงสถานะ "รอตรวจสอบ" แก่ผู้สมัคร   <- UC-11 main flow ขั้น 6

## Quality Requirements
- NFR-USE-01 นักศึกษาต้องสามารถกรอกข้อมูลและส่งใบสมัครได้โดยระบบแสดงข้อผิดพลาดที่ชัดเจนเมื่อข้อมูลไม่ครบถ้วน
- NFR-DATA-01 Draft และข้อมูลการสมัครที่ผ่านการตรวจสอบต้องถูกบันทึกอย่างถูกต้อง และเจ้าของต้องสามารถเรียกดูได้ภายหลัง
- NFR-SEC-01 ระบบต้องจำกัดการเข้าถึง Draft และข้อมูลการสมัครของนักศึกษาให้เฉพาะเจ้าของบัญชีหรือผู้ใช้งานที่มีสิทธิ์
- NFR-REL-01 ระบบต้องไม่บันทึกหรือแสดง Draft ที่ข้อมูลหรือเอกสารไม่ครบถ้วนเป็นใบสมัครที่ส่งแล้ว

## Acceptance Criteria
- [ ] AC-ENR-01 (FR-ENR-01, FR-ENR-02, FR-ENR-04)
        Given ระบบเปิดรับสมัครและนักศึกษาล็อกอินเข้าสู่ระบบ
        When  นักศึกษาเลือกค่าย กรอกข้อมูลหรือแนบเอกสาร แล้วบันทึก Draft ก่อนออกจากระบบและกลับมาเข้าสู่ระบบด้วยบัญชีเดิม
        Then  ระบบต้องโหลดข้อมูลและไฟล์เอกสารของ Draft สำหรับค่ายนั้นให้เจ้าของบัญชีเท่านั้น และแสดงข้อมูลกับเอกสารไว้ก่อนยืนยันการส่ง โดย Draft ยังไม่ถือเป็นใบสมัครที่ส่งแล้ว

- [ ] AC-ENR-02 (FR-ENR-03)
        Given นักศึกษาเลือกค่ายและกรอกข้อมูลสมัครไม่ครบถ้วน
        When  นักศึกษากดยืนยันการสมัคร
        Then  ระบบต้องแจ้งเตือนและระบุช่องข้อมูลที่ต้องแก้ไข โดยคงข้อมูลไว้เป็น Draft และไม่สร้างหรือแสดงใบสมัครที่ส่งแล้วในรายการตรวจสอบของเจ้าหน้าที่

- [ ] AC-ENR-03 (FR-ENR-05)
        Given นักศึกษาแนบเอกสารไม่ครบถ้วนหรือเอกสารไม่ตรงตามรูปแบบที่กำหนด
        When  นักศึกษากดยืนยันการสมัคร
        Then  ระบบต้องแจ้งเตือนและให้นักศึกษาแนบเอกสารใหม่ โดยคงข้อมูลไว้เป็น Draft และไม่สร้างหรือแสดงใบสมัครที่ส่งแล้วในรายการตรวจสอบของเจ้าหน้าที่


- [ ] AC-ENR-04 (FR-ENR-06, FR-ENR-07)
        Given นักศึกษากรอกข้อมูลและแนบเอกสารครบถ้วนถูกต้อง
        When  นักศึกษายืนยันการส่งข้อมูลสมัคร
        Then  ระบบต้องตรวจสอบและบันทึกข้อมูลเป็นใบสมัครสถานะ `submitted` ในรายการตรวจสอบของเจ้าหน้าที่ และแสดงสถานะ "รอตรวจสอบ" แก่ผู้สมัคร

- [ ] AC-ENR-05 (NFR-DATA-01)
        Given นักศึกษาส่งข้อมูลสมัครครบถ้วนและระบบบันทึกสำเร็จ
        When  นักศึกษาตรวจสอบข้อมูลการสมัคร
        Then  ระบบต้องแสดงข้อมูลการสมัครที่บันทึกไว้และสถานะเป็น "รอตรวจสอบ"

## Assumptions & Open Questions

- ASM-01 นักศึกษามีบัญชีผู้ใช้งานและสามารถเข้าสู่ระบบได้ก่อนสมัคร
- ASM-02 ค่ายที่นักศึกษาสามารถเลือกสมัครได้ต้องอยู่ในสถานะ "เปิดรับสมัคร"
- ASM-03 รายการข้อมูลและเอกสารที่จำเป็นถูกกำหนดไว้ก่อนเปิดรับสมัคร
- ASM-04 เมื่อส่งใบสมัครและตรวจสอบข้อมูลสำเร็จ ระบบเก็บสถานะเป็น `submitted` และแสดงแก่ผู้สมัครว่า "รอตรวจสอบ"
- ASM-05 นักศึกษาสามารถสมัครเข้าร่วมค่ายได้เพียง 1 ครั้งต่อค่าย
- ASM-06 เมื่อใบสมัครถูกส่งแล้ว นักศึกษาจะไม่สามารถแก้ไขข้อมูลหรือเอกสารได้ด้วยตนเองจนกว่าจะมีการประกาศผู้เข้าร่วม และการแก้ไขข้อมูลภายหลังจะทำได้เฉพาะโดยคณะกรรมการ
- ASM-07 แต่ละค่ายกำหนดข้อมูลและเอกสารที่จำเป็นในการสมัครภายใต้ความเหมาะสมของค่ายเอง
- ASM-08 ระบบยังไม่ได้กำหนดประเภทไฟล์และขนาดไฟล์ที่รองรับสำหรับเอกสาร และจะกำหนดในภายหลังตามความต้องการของแต่ละค่ายและความเหมาะสมของระบบ
- ASM-09 Draft มีได้หนึ่งรายการต่อบัญชีผู้สมัครต่อค่าย ผูกกับบัญชีเจ้าของเท่านั้น และเก็บข้อมูลฟอร์มกับไฟล์เอกสารจริงไว้ได้แม้ยังไม่ครบหรือยังไม่ผ่านการตรวจสอบ โดยไม่ต้องผ่าน Validation สำหรับการส่งใบสมัคร ผู้สมัครที่กลับมาเข้าสู่ระบบด้วยบัญชีเดิมต้องโหลดและแก้ไข Draft ของตนเองได้ Draft ไม่ถือเป็นใบสมัครที่ส่งแล้วและไม่ปรากฏในรายการตรวจสอบของเจ้าหน้าที่ เมื่อยืนยันการส่ง ระบบจึงตรวจสอบข้อมูลและเอกสาร หากไม่ครบให้แจ้งส่วนที่ต้องแก้ไขและคง Draft ไว้ หากผ่านให้สร้างใบสมัครสถานะ `submitted` และย้ายข้อมูลกับเอกสารจาก Draft ไปเป็นใบสมัครที่เจ้าหน้าที่ตรวจสอบได้
- ASM-10 ระบบจะแจ้งเตือนผู้สมัครเมื่อใบสมัครได้รับการอนุมัติ และผู้สมัครสามารถตรวจสอบสถานะใบสมัครได้จากระบบ
- Open Questions: ไม่มี
